The Vision

Solo founders run marketing across too many disconnected tools (Instagram, Gmail, Google Ads, GA). They get overwhelmed by complex dashboards and have no one to ask for clear answers. Furthermore, they fear losing control over their sensitive business data to unknown cloud vendors.

Business OS solves this. It connects to your accounts via OAuth, normalizes everything into a canonical domain model, and lets you chat with an AI that only sees your structured, validated data. The entire workspace operates as a Local-First application powered by SQLite.

Key Features

Feature Description
🔒 Local-First SQLite database on your machine. Zero cloud dependency.
🧠 Trust Pipeline 6-stage ingestion (Adapter → Validate → Normalize → Persist). Bad data never reaches the LLM.
💬 Conversation-First UX Chat interface. Ask "Why did CPA spike?" → get a chart + 2-sentence insight + actionable recommendations.
📊 Canonical Domain Model Platform-agnostic normalization (e.g. mapping Instagram and Google Ads spend into unified TimeSeriesMetrics).
⚡ Dual-LLM Fallback Primary OpenRouter integration with fallback provider and local heuristic logic.

System Architecture

Decoupled multi-process monorepo combining highly responsive UIs with heavy backend ingestion pipelines.

The architecture is built to withstand high concurrency from multiple data syncs while maintaining a snappy frontend chat experience. It separates concerns across two main applications running in parallel.

The Stack

  • Frontend (Web): Next.js 14, Tailwind CSS v4, React, ECharts, running on port 3000.
  • Backend (Server): Fastify HTTP/WebSocket API running on port 4000. Powers the Trust Pipeline, Brain Interface, and Analytics Event Bus.
  • Database: Workspace-isolated local SQLite databases via native node:sqlite and Drizzle ORM.
  • Package Manager: pnpm workspaces for managing 8+ distinct internal packages (connector-sdk, brain-sdk, context-engine, etc.).

Engineering Culture & Quality

The project is governed by strict, enterprise-grade engineering practices designed for long-term maintainability.

  • ADR Enforcement: Architectural Decision Records (ADRs) are required for all major design choices.
  • Strict Tooling: TypeScript strict mode, Markdownlint, Commitlint (Conventional Commits), and Husky pre-commit hooks.
  • Automated Validation: Custom CLIs (pnpm validate:adrs, validate:docs, validate:context) verify documentation freshness, vocabulary usage, and cross-referencing.
